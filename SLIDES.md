## Slide 6: Interview Findings

**Title:** What We Learned from the User

**Content to include:**

- Common concerns include broken chairs, weak or damaged electric fans, missing extension wires, dirty classrooms, and non-working outlets.
- The current reporting method is usually telling the professor.
- The main difficulty is not knowing who is responsible or whether the concern was received.
- The user prefers reporting through a mobile phone.
- The user wants a short form, dropdown categories, photo upload, and a status tracker.
- The user is concerned about privacy and whether reports will actually be handled.

**Purpose:** Summarize the most important interview insights before moving into needs and persona.

## Slide 16: Dashboard Features

**Title:** Dashboard Features

**Name and explain the features shown in the dashboard:**

- **Home Feed:** Shows visible classroom concerns with newest reports first.
- **Status Filter:** Lets users filter reports by status.
- **Report Status:** Shows if a concern is Submitted, In Review, In Progress, Resolved, or Rejected.
- **Category and Location:** Helps users understand what the concern is and where it is located.
- **Photo Preview:** Helps provide visual proof of the concern.
- **Upvote and Downvote:** Lets users show support or disagreement on reports.
- **Create Report:** Opens the form for submitting a new concern.
- **Track Report:** Lets users view their own submitted concerns.

**Purpose:** Make sure the audience understands what each dashboard part does.

## Slide 20: Design Guidelines Applied

**Title:** Design Guidelines Applied

**Main idea:** Use screenshots from the website and add arrows/callouts that point to specific design guideline examples.

**Suggested screenshot approach:**

- Use one screenshot of the dashboard or create report page.

- Each arrow should name the design guideline that is being applied.

**Possible callouts:**

- **Visible buttons:** Point to Report Concern or Submit button.
- **Clear instructions:** Point to form labels or page heading.
- **Readable text:** Point to report title/status text.
- **Proper spacing:** Point to the form layout or dashboard list.
- **Simple words:** Point to buttons like Submit, Back, Check Status, or Report Concern.
- **Familiar icons:** Point to camera/upload/search/status icons if shown.
- **Consistent labels:** Point to repeated status/category labels.
- **Easy navigation:** Point to navigation menu or dashboard tabs.
- **Organized information:** Point to report cards or report detail sections.
- **Mobile-friendly layout:** Mention that the interface should adapt well to mobile phone screens.
